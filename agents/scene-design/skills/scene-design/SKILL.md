# 场景设计主 Skill

先读当前角色 AGENTS.md。接收上游已经确定的“谁在这里、发生了什么、观众应理解和感受什么”，再设计它们怎样在空间里被看见。不得自行补写人物动机、事件原因或结局；缺失的关键故事信息返回总控。空间与美术细节可以提出方案，但不能暗改剧情。

## 按需加载

先看总控包的 visual_style，按其中的 skill 路径读取当前一份风格方法。未指定时新设计采用写实电影；目录见 ../../styles/风格目录.md，机器索引见 ../../styles/catalog.json。不要把题材（如巨构/科幻）当成媒介风格，或把“电影感”自动写成概念画。只修改风格设定不等于已经转换现有图，重新出图仍需按具体授权及既有人审流程执行。

## 设计顺序

需要制图或改图时，先读取 [静态图输入策略](../../../../references/static-generation-input-policy.md)。整体姿态/构图/机位重设使用fresh_redraw，旧生成图不得作任何输入；用户明确局部编辑才使用local_edit。原始参考负责设计依据，不能以“复用素材”为由继续锁住失败轮廓。

1. 读懂上游交接的剧情、地点功能、已知/未知信息和情绪目标，将其概括成一句场景表达任务；这是忠实转译，不是新编故事。仅接收当前镜头所需背景，不复述整部剧本。
2. 确认权威素材及当前状态，标出可改/不可改/待确认项。现有素材不必重新设计。
3. 接收镜头的景别、机位、视角、可见边界与必要时长。分开记录镜头景别、空间层次、大小体块。
4. 先设计空间事实：体块、通路、位置、尺度、遮挡、接触与出入关系，再判断这个机位看到什么。
5. 组织第一眼、第二眼、细看获得的信息。前中后各自承担叙事、空间或气氛职责，不能只是三张独立背景板。
6. 把情绪与意义落实成形式、功能、局部变化及光色。装饰、裂纹、雾和发光线必须说明作用，不能平均铺满。
   每一项设计先给故事依据：它因何存在或变化、反映谁的处境、帮助观众读到什么；可以共同支撑同一条叙事，不强迫所有物件独立象征。读取 ../../references/story-driven-scene-design.md，把故事因果转为空间和可见关系，不照搬具体案例的元素。
7. 只在需要时做构图草案、灰阶、同源空间预览或静态图；解释方案并交总控已有的人审节点。

用“秩序基线 + 局部异常 + 因果线索”可设计规则被破坏的暗示，但这是条件性叙事手法，不是破损的固定含义。自然老化、事故与人为破坏可能有相同表象，应区分证据和推断，不擅自增加剧情。完整演示见 ../../examples/order-and-breach.md。

## 输出与反馈

静态产物交接前按 `../../../../references/subject-intent-motion-review.md` 审核实际图中各主体的表达作用、绘制合理性、生命/材料、支撑与连接，形成 scene_package 内的 `subject_audit`。覆盖远景与遮挡处可见主体，不只核对提示词中计划绘制的物件；绘制疑点先交总控，不能指望视频自动修好。动作决定交动作角色补充，总控最终核对；本角色不凭表格自行更改故事或已经认可的图片。

交付 ../../templates/scene-package.md 中当前任务需要的内容。图像文件未产出时标 proposed；存在只代表 available，经人审后才可标 accepted。静态图不能证明动态过程或多机位空间完全一致。

总控拿设计依据、必要预览和差异交人审，不拿一串自评分数代替判断。发现不成立，定位到空间、构图、连续性或叙事关系，返回证据及最小修改建议，停止自动反复生成。
