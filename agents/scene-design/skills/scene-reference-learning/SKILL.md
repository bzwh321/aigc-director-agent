# 场景参考学习与沉淀

## 什么时候学

设计遇到真实知识缺口、需要陌生题材/文化依据、当前参考无法解释结构，或用户要求研究时检索。先读角色 references/learning-index.json 的命中摘要，再按需打开来源，不每次从零搜索、不加载整个图库。

网络学习为随任务触发，不是自动后台服务。通常先用1–3条聚焦查询、读少量相关原始来源；信息已足够支持本次设计就停止。找不到可靠依据时报告未知和可选方案，不不断扩大检索或自动出图。定期学习的频率、范围和预算要另外确认。

## 从哪里学什么

优先游戏开发者/原艺术家的制作拆解、GDC原讲者资料、工作室技术文章；工程细节优先官方文档。社区用于发现线索和反馈，转载截图追溯原出处。画面分析和作者工作流程不能互相冒充；只读到讲座摘要时写明，不能声称看完视频。

查询由“当前设计问题 + 场所/题材 + 希望理解的关系”构成，例如 environmental storytelling order disruption architecture、foreground midground background environment composition、blockout visual hierarchy。文化和历史事实另查相应权威来源。不要把一张游戏截图当成现实建筑或心理学证据。

## 拆解与迁移

分栏记录：原图/原文可确认的内容、自己的解释、本项目拟采用的决定。关注空间功能、大形、观看顺序、路径与遮挡、尺度、光色职责、损伤/使用因果，以及什么不应照搬。复制表面的塔、雾和金边不等于学习设计关系。

游戏的探索时长与可互动线索迁移到视频时，重新检查固定机位、镜头停留时间和可见性。保留必要的未知，不强迫观众读出唯一剧情。原作者的意图、具体软件参数、真实尺度未核实时不补全。

## 有证据地沉淀

在 references/learning-index.json 更新已有ID或新增一条：问题、方法摘要、角色/主题、来源URL或本地路径、作者与访问日期、适用/不适用条件、证据类型、状态、验证/失败结果。以来源与设计问题去重，网页没变化不重复保存。

状态分开：source_checked=来源已读、candidate=迁移假设、project_validated=在指定项目得到实际结果与人审反馈、rejected=已证伪或不适用。读完资料不直接升级为已验证；用户认可的创作方向也不是所有情境的客观规律。失败或反例同样记录，并保留适用范围。

本次采用的条目摘要和引用写入当前项目 .director/memories.json，原媒体只登记到素材索引。不把整个网页、完整图库或所有经验传给每个角色。新增门禁须有真实重复问题和用户同意，不能从一次失败衍生成普遍限制。

保存参考要核对具体许可、署名和用途；网页可看不等于图片可商用，未确认许可时只保留链接和必要分析。不得绕过付费墙或批量下载。新模型/生成/外部上传要由总控按本轮授权处理，学习本身不授权试验费用。
