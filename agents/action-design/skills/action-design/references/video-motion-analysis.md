## 学习目标与边界

从用户认可的参考视频中提取可追溯的动作、时间、镜头和效果关系，再供动作设计及提示词角色使用。优先理解已有好片，不默认重新制作简化人物预演。提取动作结构不等于找回原始提示词，也不等于保证生成模型能复现。

区分三层：

- 几何数据：人体关键点、关节姿态、物体点轨迹、可见性。
- 动作解释：谁蓄力、何时启动、谁攻击/响应、何时可能接触、如何停稳。
- 镜头与风格解释：景别、剪切、运镜、变速及环境反馈如何制造观感。

模型输出属于估计。静态/遮挡线索不能当成隐藏动作的证据；无标定时不能把屏幕像素位移写成米/秒或真实打击力。

## 推荐学习顺序（尚未实施）

1. 先选一段5–10秒、有明确学习目标且允许使用的参考片；保留原文件、来源、原始帧率/时间戳、是否剪辑变速等信息。
2. 用分镜检测加人工核对找切点；跨镜头不直接延续同一条点轨迹或当作真实空间连续移动。
3. 用视频理解模型做粗读，分开可见事实与动作/情绪解释。模型引用的事件要带证据帧和时间区间。
4. 对手部收势、脚底蹬离、剑刃交会、重击等短事件，回到更密集的原始帧检查。不得用插帧生成的中间画面充当真实接触证据。
5. 按需用全身姿态或点追踪核对，不一上来安装全部工具。双人交叉时检查身份是否串线；剑尖/手腕被遮挡时保留不确定标记。
6. 单独处理摄影机影响：参考多个稳定背景点，区分主体相对运动和共同画面位移。二维背景补偿不能保证恢复三维路径，也不能总能区分变焦与前后移机。
7. 人工确认重要事件，再提炼成可迁移的节奏、路径和镜头方法，交给动作/提示词角色；不复制角色身份、服装、布景或无关剧情。

优先验证Qwen3-VL粗读与逐帧复核；几何细节不足再评估MMPose。CoTracker与GVHMR先作为研究候选，许可和实际适用性未核准前不纳入商业生产。不同工具顺序运行，先限制片长/画面大小，实测本机资源后再定批量规模；不承诺某显卡可实时处理。

## 输出格式

复用现有subject_id与镜头表，不另造重复台账。可用紧凑表或JSON，每个事件包含：

| 字段 | 要回答的问题 |
|---|---|
| shot_id、start/end、frame_refs | 属于哪镜、哪段、哪些原始帧支持？ |
| subject_ids、visible_action | 谁做了什么？对象是否跨遮挡串线？ |
| hand/foot/body | 手、脚、身体可见变化及关联，不见的部分写未知 |
| weapon_path、contact_evidence | 武器相对何物移动，接触是看见、推测还是仅由声音暗示？ |
| camera、cut、retiming | 运镜、切镜、素材内变速各是什么？是否能确定？ |
| rhythm、response、environment | 蓄、放、停、受击与衣物/碎石/雨水怎样衔接？ |
| confidence、unknowns | 哪些可信，哪些需人确认？数值置信度不冒充实际正确率 |
| transferable_method、prompt_draft | 哪个结构值得学？如何改写成当前故事的提示词？ |

示例句式（非对实际视频的分析结果）：
“主体A先压低重心；后脚蹬离在帧X可见；剑刃接触被衣袖挡住，仅可确认双方随后分离，因此接触时刻标为待核对，而不是写成确定碰剑。”
