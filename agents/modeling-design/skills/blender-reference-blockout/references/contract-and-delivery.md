# 合同、恢复与交付

小任务可以在项目记录中写同等信息，无须为了格式建空文件。复杂或可恢复任务推荐 `modeling_contract.json`，字段见相邻 `../assets/modeling-contract.example.json`；示例是字段示范，不是默认场景或完成记录。

## 核心字段

- `schema_version`：`blender-blockout/v1`。
- `asset_id`、`mode`、`request`：当前建模单元、分析/制作/检查/修改、原始目标。
- `reference_images`：ID、真实文件路径、主要职责、内容哈希；无图片允许空列表。引用只代表文件，不替代实际看图。
- `scale`：`meters_per_unit`（相对尺度未知可 null）、`source`、`basis`；工程内部坐标正向另记。
- `facts`：事实 ID、statement、status、source；未确认背面/深度用 design_assumption，不称实测。
- `components`：ID、parent、method、必要尺寸与来源、锚点、与其他组件关系；不要把全部类别套固定零件树。
- `output_root`、`deliverables`、`review_views`：本轮目标路径、预期文件、检查机位；没有生成前只是计划。
- `preserve`：不可更改的原件/已认可形体；可空。

`scripts/check_contract.py` 检查结构、有限正数、组件/父级引用和循环、输出路径范围，按需核对输入文件 SHA-256。它不验证图片语义、尺寸是否真实或人类身份，更不会代填认可。

## 运行与恢复

工程与结果存项目输出目录，不存 Skill 安装目录。新版本使用明确的版本号/归属集合；重跑同版本前检查已有输入指纹、产物与状态，恢复或更新本轮归属数据，不能每次复制一套重叠模型。不得为“幂等”清空无关内容。

输入内容变更应重算源指纹；旧任务不能只因路径未变就沿用完成状态。修改某组件，重新核查其依赖锚点、接触、相关视图和交付；其余未变化认可不机械作废。

## 实际交付记录

制作后在项目记录中填写：工作 .blend 的实际路径/哈希、保存与可选重开结果、组件清单、生成的真实视图、检查项状态、测量方法及覆盖缺口、未解决问题、版本和来源。首次执行失败后给现场证据与建议，不自动反复生成。

状态含义：`planned` 是计划；`built_unverified` 是实际建立但未核查；`technical_checked` 只指所列数值检查；`visual_reviewed` 只指已看过的视图；`user_accepted` 需要该版本对应的用户认可。任一状态不能替代其他状态。

没有得到最终认可时照常交付真实文件和待审说明，不自称已通过。白模的成功不外推为拓扑适于动画、制造水密、法规合规或真实动力学稳定。
