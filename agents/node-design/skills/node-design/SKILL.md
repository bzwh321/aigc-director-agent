# 节点设计 Skill

先经 `../../../../方案库/SKILL.md` 的决策。使用总控传来的本镜 `solution_decision`，仅按 recipe_id 查询该方案与候选服务；未知事实返回总控，不绕过库直接提交。当前节点能力核对后把实际选择与证据写入合同。API Key只使用库中的凭据引用，选型上下文不得含值。

最终选择权属于总控，记录 selected_by=director。读取镜头合同与本机真实节点清单/端口schema，区分本地扩散与云端API。不得凭旧画布或历史名称声称节点可运行，也不把本地LoRA、步数、精度参数套到托管API。

用户明确指定平台、模型和计费钱包时，把它们作为选型硬约束先过滤候选，再由导演选具体节点。`H3 + RunningHub + RH币` 不等同于MiniMax官方直连或RunningHub人民币标准API；服务、模型、模式、币种/钱包分别记录。核对当前应用schema、费用字段及钱包，不能仅因同名模型或API Key可用就认定符合要求。项目偏好见其AGENTS/run记录；`b站巨构自动更新`于2026-10-12明确选择RunningHub H3与RH币，排除Seedance2.0，此范围不扩展为其他项目的全局默认。
简单起点可I2V，简单起止用首尾帧，需多源身份/运镜/动作选参考模式；Edit只修已有真实运动的源视频，不用它发明缺失动作。节点限制触及输入、时长或场景时回给总控，禁止暗改设计。
每镜独立分组：参考、提示词、预演/首尾帧、生成、预览、保存及审核说明。共享素材只登记一次，结果节点标明真实生成或本地模拟；文件名包含镜头号与版本。
先本地校验输入、媒体比例/时长、节点和文件路径、连接类型。云端节点默认禁用。执行前展示服务/模型、任务数、时长、分辨率、参考计费、费用上限与停止线。未知提交状态先查原任务，禁止重发POST。
输出每镜 mode、node_class、inputs，capability_evidence（来源与核对时间）、cost_preview、auto_retry=0。凭据只引用用户既有本地配置，不写画布与产物。接口返回成功仍需总控审片。

实际试制须分别记录“服务/币种/输出规格已验证”和“主体动作已通过”。参考图模式或带提示词增强的应用，不因参数中写了固定机位、局部呼吸、保持不动就视为执行成功；对照原图检查第一帧构图，以及主体相对固定参照物的运动。失败经验限定到具体应用、模式和样本，不扩大成整个模型的能力结论。适用的每镜次数及总预算从当前授权账本读取；跨日恢复不清零。若次数用尽，可提供明确标注未通过的试制片供查看，不把它登记为合格成片或允许定时器再次提交。
