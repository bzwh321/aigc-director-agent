# 决策输入与接入

纯本地只读：`python 方案库/decide.py --input <事实JSON>`，或者 stdin 输入对象。
导演 V3 每次 `workflow.py` 规划自动经过本库，结果在 `solution_decisions[shot_id]`。原 V2 规划与旧 G1设计就绪也附方案决策（顶层 `solution_facts` 加每镜覆盖），保留旧阶段兼容；未知事实返回缺口，不把旧阶段状态当成绕过入口的理由。

## 最小事实例子

```json
{
  "input_kind": "image",
  "operation": "generate",
  "subject_motion": "none",
  "camera_motion": "pan",
  "needs_new_pixels": false,
  "hard_end_frame": false
}
```

此例选 `local-still-pan`。把主体改为 required 但仍禁止新像素会返回冲突，而非偷偷调用生成。

V3 在 `brief.solution_facts` 放共享事实，在 `shots[].solution_facts` 放本镜覆盖；未知省略或用字符串 `unknown`。不能将原图/视频、凭据或完整剧本塞入事实卡。

| 字段 | 取值/含义 |
|---|---|
| input_kind | image / video / none / unknown；指本次模式决策的主要输入，不是所有附件 |
| operation | generate / edit / extend / post / lipsync / unknown |
| subject_motion | none / required / unknown；与摄影机运动分开 |
| camera_motion | none / pan / tilt / zoom / reframe / translate / complex / unknown；pan不自动证明三维位移 |
| needs_new_pixels | 布尔或unknown；是否需要生成新的表演/透视/内容 |
| hard_end_frame | 是否必须锁定确切尾帧，不能把缺失当false |
| endpoints_compatible / simple_middle_action | 首尾兼容性与中间动作可行性已经评估 |
| real_motion_verified | Edit要保留的实际运动是否已看片确认，不是仅文件存在 |
| source_accepted | 续写/口型所用源片是否已经接受 |
| multiple_reference_roles / dynamic_reference_verified | 多参考职责/动态样本已经检查 |
| locked_background / crop_margin_verified | 背景锁定、裁切余量已核对 |
| visible_speaker / audio_ready | 可见说话人及确定原干声 |

只允许以上字段进入决策，其他键忽略且不回传；布尔必须是真实JSON布尔，字符串true/false不算。复杂事实不通过猜测强压成布尔。

## 结果与复用

- SELECTED：只选中制作方法，服务列表仍是候选；绝不等于当前节点已验证或已获执行授权。
- NEEDS_FACTS / INVALID_FACTS：补一个真正影响模式的缺口，不增设人审阶段。
- DIRECTOR_CHOICE：当前规则不覆盖或有约束冲突，总控处理，不循环调用模型。
- NOT_NEEDED：例如没有可见嘴巴，不需修口型；不是批准其他方案。

`decision_fingerprint` 绑定决策事实与方案库内容，不等于媒体哈希或执行凭据。项目复用记录另外保存输入素材hash/版本、服务schema版本、具体节点、能力检查时间、预算批准引用。任一执行相关输入变化须重核；不能只凭相同模式指纹沿用旧费用授权。

节点与提示词任务只拿当前镜头的决策摘要。方案库缺失/损坏时停止生成方案交付，不静默跳过。没有方案决策不应提交外部视频任务；本程序本身不代理外部执行器，不能拦截用户在第三方界面手动提交。
