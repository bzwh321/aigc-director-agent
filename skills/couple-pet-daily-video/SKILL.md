# 夫妻日常萌宠短片

把用户和伴侣的真实日常转译为用户自家长毛三花猫的真实幼年 Q 版与一只淡粉小猪的短视频。可爱来自真实幼体比例、反应节奏和关系，不把角色画成玩偶、3D 卡通或穿着人类服装的拟人角色。

本 Skill 位于 AIGC 导演根目录的 `skills/` 下。导演根目录为本 Skill 的 `../..`。

## 只沉淀四类事实

1. **角色资产**：猫、猪的稳定外形、比例、可辨识特征和已认可视图。涉及新建或替换角色图时读 [角色资产](references/character-assets.md)。
2. **对话与配音分镜**：原话、说话人、停顿、重音、情绪、反应镜头和音画时间。设计对白时读 [配音分镜](references/dialogue-storyboard.md)。
3. **动作与场景**：每句台词对应的可见动物动作、空间位置、道具接触、镜头和生活环境。设计镜头时读 [动作与场景](references/action-and-scene.md)。
4. **导演交接**：把已整理的材料交给导演 Agent，由导演完成视频方案选择、专业能力调度、合同、制作和审片。进入制作时读 [导演交接](references/director-handoff.md)。

使用 RunningHub H3 处理多节拍对白、晚出现道具、同场景重复出入或昼夜变化时，按多节拍对白的通用方法编排，不套用特定项目的实测记录。

不要在 Skill 中保存整段私人聊天历史。只保存用户确认可复用的角色设定、表演规律、场景规律和已验收资产；每集原始对话放在该集项目目录。

当前猫身份权威文件是 `assets/characters/cat-home-childhood-turnaround-v005.png`。`cat-turnaround-v001.png` 与 v002–v004 仅作历史和失败经验，不得用于新场景、视频或身份参考。当前小猪身份权威仍为 `assets/characters/pig-turnaround-v001.png`。

## 收到一段对话和场景后

先保留用户原意和夫妻关系中的语气，不为了“更像短视频”擅自制造冲突、鸡汤或反转。信息足够时直接整理，不发长问卷；只有下列缺口会实质改变结果时才追问：猫猪分别代表谁、必须保留的原话、目标时长、关键动作或场景物件。

输出一份紧凑的单集 brief：

- 原始对话与允许改写范围；
- `speaker_a` / `speaker_b` 到猫或猪的映射；未确认前保持占位，不猜测；
- 一句场景事实、情绪走向和结尾停点；
- 竖屏 `9:16`，逐镜秒数、台词/停顿、主体动作、反应、景别与机位；
- 使用的角色图版本、连续性约束和需要新增的资产；
- 配音、口型、环境声、音乐及静音段的处理；
- 本轮静态图或视频生成的次数、服务、预算状态与失败停止条件。

## H3 全模态默认视频方式

本 Skill 的视频节点默认采用 **H3 全模态原生有声生成**。每个节点在一次生成中共同完成画面、动物动作、中文对白、声音表演、环境声和动物口型，不再采用“静态图生无声视频，再用外部 TTS 配音或驱动口型”的制作路线。

- 静态图只用于角色身份、场景构图和关键状态的人审与视觉参考，不把逐张静态图机械动画化当作成片方案。
- 有对白的节点把逐字台词、说话角色、声音性别/年龄感、情绪、语速、重音、动物化口型、身体动作和镜头动作一起写入全模态任务；开启 H3 原生有声，外部音频输入保持为空。
- 情绪不是一个笼统形容词。每条对白必须在生成前设计逐句或逐短语的情绪弧线，包括起始心理、情绪推进、重音、停顿、语速变化、音量变化、呼吸和句末落点，并把这些声音节拍绑定到同一时刻的眼神、口型、头耳、身体或道具动作。
- 无对白的节点仍走同一全模态路线，由 H3 同时生成动作、接触声、环境声与必要静音；不得为了方便退回无声图生视频。
- 当前默认声线是可爱的童声：猫为女性童声，小猪为男性童声。每集可以按用户要求调整，但不得擅自克隆真人声线。
- 说话者必须在正面或三分之二正面清楚露出口鼻，口型随本次原生对白同步；听者只能做眼神、耳朵、头部和身体反应，不能跟着一起张嘴。
- 每个节点都要有连续的起始状态、动作推进、对白/声音节拍和结束状态，不能只让一张静态图轻微眨眼、轻推镜或原地开合嘴。
- H3 原生有声若出现台词错误、声音不清、情绪与剧情不符或过于平读、无口型、人嘴人牙、角色漂移或动作不成立，立即停止并返回该节点证据；不自动改用 TTS、无声图生视频或其他服务。
- 外部 TTS 仅在用户明确改变制作方向并单独批准对应任务与费用时作为例外，不是自动回退。

合同中把执行模式明确写为 `h3_full_modal_native_audio`，并逐节点记录 `native_audio=true`、`external_audio_input=none`、原生台词、声音设定、情绪弧线、短语级韵律提示、口型对象及失败停止条件。方案名称不得写成普通 `image-to-video`。

## 逐镜六项强制编排

每个拟生成镜头必须先由导演 Agent 调用并收齐以下四个专业角色的当前镜头结果；这是本 Skill 的强制调用条件，不是可选建议：

- `shot-design`：分镜目的、景别、轴线、视线、起止状态、时长、切点、转场动机，以及摄影机运动的类型、路径、起止和停止状态；
- `sound-design`：原生对白的声线与短语级情绪表演、重音/停顿/呼吸、口型对象，以及接触声、动作声、环境声、静音区和声音桥；
- `scene-design`：当前空间、角色路线、接触面、遮挡、道具状态、光线与前后镜连续性。已有场景可以复用，但必须完成核对并明确返回，不能静默跳过；
- `action-design`：逐主体动作卡、驱动与意图、整体路径、局部关节/口鼻/头耳、重心、接触点、惯性和材料响应、次数、停止条件、末态及下一镜接力。

导演把以上结果整合为每镜唯一的 `director_shot_package`，至少包含六个区块：`storyboard`、`camera`、`voice`、`action`、`scene`、`sound_effects`。其中运镜不能只写“推近”“跟拍”，要写旋转/物理位移/焦段变化、速度、何时开始停止及与主体动作的关系；转场不能只写“硬切”，要说明前镜留下的动作/视线/道具/声音，下一镜怎样接收。

任一专业角色未实际调用、交付版本不明、六项缺失或互相冲突时，禁止进入提示词编译、节点选择和付费生成。提示词角色只能编译已通过的六项合同，不能临场代替动作、声音或场景设计。导演审片时逐项对照实际视频；依赖本地裁切才能删除回位、错肢体或僵硬停顿的情况要登记为生成缺陷，不能当成前期设计已经成立。

## 创作边界

- 默认保持猫和猪的真实动物身体结构。允许用眼神、停顿、转头、靠近、躲开、轻碰、叼取等动作表达人的关系；需要站立、拿物、做饭等强拟人动作时，先明确它是刻意的喜剧设定，并让导演评估可实现性。
- 默认让当前说话者进入正面或三分之二正面特写，由 H3 原生对白驱动清楚但仍属于动物结构的口型；只有用户或剧情明确要求画外音时才允许 `offscreen`。听者保持真实反应，不跟随对白开合嘴。
- 一句对白不机械等于一个镜头。优先保留问答节奏、听者反应和生活中的小停顿。
- 每镜分别写主体动作、摄影机动作和环境动作。相机移动不等于动物在动；背景运动也不能替代表演。
- 场景来自用户给出的生活事实。可整理空间与光线，但不凭空加入改变事件意义的地点、人物、宠物或道具。
- 首批角色视图是连续性基准，不是每个镜头都必须完整输入的拼图。按镜头选最接近角度的单一视图或裁切，避免把整张多视图表误当成同场多只动物。

## 调用导演 Agent

准备好单集 brief 后，按 [导演交接](references/director-handoff.md) 调用 `../../AGENTS.md` 与 `../../SKILL.md` 所定义的 AIGC 导演。导演负责理解整集、按需调用声音/镜头/场景/动作/提示词/节点能力，并在视频执行前经过 `../../方案库/SKILL.md` 选择当前可用方案。

对本 Skill 而言，声音、镜头、场景和动作不是“按需可跳过”角色，而是每个生成镜头的必经专业交付；详细字段与调用证明见 [导演交接](references/director-handoff.md)。

本 Skill 是外层组织入口，不冒充导演已被调用。任务包带 `origin=couple-pet-daily-video` 与 `director_invocation_active=true`；导演收到后直接工作，不递归调用本 Skill。

继续沿用导演 V3 的三个人审点：静态图、制作合同、最终结果。用户对角色基准图的认可不等于批准视频生成；合同通过也不自动扩大付费次数。任何生成失败或明显质量问题先返回，不自动重试、换模型或改用其他服务。

## 完成标准

- 猫与猪的外形能追溯到已认可的角色资产版本；
- 每句保留台词都有明确说话人、时间和表演意图，听者反应可见；
- 动物动作符合身体结构、接触和重心，场景与道具前后连续；
- 每个生成镜头都有可追溯的镜头、声音、场景、动作角色调用结果，并完成分镜、运镜、配音、动作、场景、音效六项对照审片；
- 导演任务已实际调用并有返回记录，不能把“已准备任务包”写成“导演已完成”；
- 实际成片为竖屏，每个节点均能追溯到 H3 全模态原生有声任务，音画时长、原生台词、声线、情绪弧线、重音与停顿、口型对象、说话顺序和结尾停点均已检查；
- 用户最终确认前标记为 `awaiting_final_review`。
